# Farsighted | two-minute product demonstration

**Goal:** 1:50–1:55 total (strictly not over two minutes). Record a screen demonstration of the app using *actual* pipeline-generated JSON, not organizer reference answers. The screen/tab order follows the user story: problem → evidence → requirement → change → handoff.

| Time | Screen and action | Suggested narration |
|---|---|---|
| 0:00–0:17 | **01 Story**. Show title and product-to-handoff line. | “When an automotive component changes, an engineer still has to find the right obligations across hundreds of regulatory pages. Farsighted connects the product evidence to requirements an engineer can actually inspect.” |
| 0:17–0:35 | **02 Product input**. Show specification and exploded view. | “We start from the component specification and drawing. The first stage builds a grounded product profile; anything that isn't supported stays unknown instead of becoming a guessed product feature.” |
| 0:35–0:51 | Back to **01 Story**; point to evidence and screening stages. | “We index regulation PDFs, screen applicability and carry forward the relevant text with its context, rather than asking a model to answer from memory.” |
| 0:51–1:20 | **03 Requirements**. Pick one real row, scroll to its requirement and source. | “The result is a set of atomic engineering requirements. Here is one generated obligation and exactly where it comes from: regulation, version, page and paragraph. An engineer can check the source and decide what the design must satisfy.” |
| 1:20–1:39 | **04 Changes**. Select a clear modified or added row and reason. | “Regulations also evolve. Our second workflow compares existing requirements with new regulatory text and proposes additions, modifications or removals, with an explanation and citation.” |
| 1:39–1:53 | **05 Handoff**. Point to export and review boundary. | “We add validation and conservative review safeguards, then export structured JSON for engineering review. Farsighted shortens the search and makes decisions traceable—it does not claim automatic certification.” |

## Presentation rules

- Use **only data actually present** in the loaded JSON. The numbers on Story are generated from that data. You may mention them verbally, but they aren't proof of accuracy.
- No hardcoded “we found X regulations” or leaderboard scores in the narration. Farhan may change presets or run a new case.
- If the optional pipeline output is from a different case, say it is a separate worked example; never imply it is the same front-bumper case.
- Do not claim that clicking this UI re-runs extraction. The video demonstrates the **result viewer** and explains the code pipeline behind it.
- Rehearse which real main requirement and change example to open before recording. Choose rows with clear complete source citations.
- Upload as an **unlisted video** (if permitted by the platform) and confirm the link is accessible to someone outside your logged-in browser.
